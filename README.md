# Marketplace Position Bot: Wildberries + Яндекс Маркет

Отдельный проект для анализа позиций товаров Wildberries и Яндекс Маркета по поисковым запросам.

Старый Prom-бот не используется как зависимость и не меняется. Из него перенесена только общая архитектурная идея: env-конфиг, SQLite база, отдельные модули для клиента маркетплейса, анализа, отчетов и точки входа Railway.

## Что уже заложено

- хранение отслеживаемых карточек в SQLite;
- анализ выдачи Wildberries и Яндекс Маркета по запросу;
- топ-5 карточек по запросу;
- поиск позиции своей карточки по `nm_id`, ID продавца или названию магазина;
- сохранение истории проверок;
- недельный график изменения позиции с автоматическим переходом на новую неделю;
- общая статистика за все время сбора данных;
- PNG-инфографика для Telegram;
- текстовый отчет для Telegram/консоли;
- заготовка Telegram-команд;
- Railway `Procfile` и `railway.json`.

## Структура

```text
wb_position_bot/
  analyzer.py      # логика поиска позиции и топ-5
  analytics.py     # недельная/общая статистика и PNG-графики
  bot.py           # Telegram-слой
  config.py        # env-настройки
  db.py            # SQLite и миграции
  models.py        # dataclass-модели
  report.py        # форматирование отчета
  wildberries.py   # клиент публичной выдачи WB
  yandex_market.py # клиент и парсер поисковой выдачи Яндекс Маркета
  target_parser.py # разбор команд добавления карточек
main.py            # CLI и запуск бота
tests/             # базовые тесты анализа без сети
```

## Быстрый старт локально

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python main.py init-db
```

Добавить карточку:

```bash
python main.py add --nm-id 123456789 --query "поисковый запрос" --supplier "Название моего магазина"
```

Если артикул WB пока неизвестен, можно добавить только запрос и магазин:

```bash
python main.py add --query "1С:Бухгалтерия 8 для Казахстана. Базовая версия" --supplier "кодерлайн"
```

Запустить проверку одной карточки:

```bash
python main.py analyze --nm-id 123456789
```

Проверить все активные карточки:

```bash
python main.py analyze-all
```

Построить график текущей недели:

```bash
python main.py week --nm-id 123456789
```

Построить график и статистику за все время:

```bash
python main.py stats --nm-id 123456789
```

## Telegram

После добавления токена в `.env`:

```bash
python main.py bot
```

Первичная привязка:

```text
/start change-me
```

Минимальные команды:

```text
/status
/help
/invite
/users
/add 123456789 | поисковый запрос | Название моего магазина
/addym 103705469335 | поисковый запрос | Название моего магазина на Яндекс Маркете
/add поисковый запрос | Название моего магазина
/list
/delete 1
/check 123456789
/checkall
/week 123456789
/weekwb
/weekym
/stats 123456789
/statswb
/statsym
/stats
```

Формат добавления Wildberries:

```text
/add АРТИКУЛ_КАРТОЧКИ_ФИРМЫ | ФРАЗА_ИЗ_ПОИСКА_WB | НАЗВАНИЕ_МАГАЗИНА
```

Бот вводит указанную фразу в поиск Wildberries и определяет позицию карточки с этим артикулом. Название магазина используется как дополнительное подтверждение продавца.

Формат добавления Яндекс Маркета:

```text
/addym ID_ИЛИ_ССЫЛКА_НА_КАРТОЧКУ_ФИРМЫ | ФРАЗА_ИЗ_ПОИСКА_ЯНДЕКС_МАРКЕТА | НАЗВАНИЕ_МАГАЗИНА
```

Бот вводит фразу в поиск Яндекс Маркета и определяет позицию указанной карточки. Для одной карточки можно сохранить несколько поисковых фраз: каждая добавляется отдельной командой.

### Дополнительные пользователи

Владелец создает бессрочное одноразовое приглашение:

```text
/invite
```

Бот вернет команду `/start КОД`. Ее нужно переслать пользователю; код не имеет срока действия и срабатывает один раз. Можно создать любое количество независимых приглашений. После подключения:

- дополнительный пользователь получает все рабочие команды, но видит только собственные записи и графики;
- владелец видит записи всех пользователей и получает результаты их ручных проверок и ежедневных отчетов;
- ежедневные запросы выполняются по одному разу, поэтому доступ пользователей не удваивает расход ReefAPI;
- автоматический отчет владельца содержит все записи, а каждый дополнительный пользователь получает только свой отчет.

Проверить доступ:

```text
/users
```

Закрыть доступ и остановить запросы пользователя, не удаляя историю:

```text
/removeuser CHAT_ID
```

Для Яндекс Маркета вместо числа можно передать полную ссылку на карточку. Бот возьмет последний числовой ID из URL:

```text
/addym https://market.yandex.ru/card/nazvanie/103705469335 | телефон | Мой магазин
```

После этого `/check`, `/checkall`, автоматический утренний отчет, `/week` и `/stats` работают одинаково для обеих площадок. В `/list` каждая запись имеет собственный внутренний `id`; безопаснее всего вызывать команды именно по нему.

## PDF-отчеты по площадкам

По общим командам бот формирует один многостраничный PDF вместо общего графика с пересекающимися линиями. Первая страница содержит сводку, затем для каждого поискового запроса идет отдельная крупная страница с собственным графиком. Источник данных не меняется: PDF строится по сохраненной истории автоматических проверок из `position_checks`.

- `/weekwb` — запросы Wildberries с проверками за текущую неделю;
- `/weekym` — запросы Яндекс Маркета с проверками за текущую неделю;
- `/statswb` — все запросы Wildberries за все время, включая удалённые из отслеживания;
- `/statsym` — все запросы Яндекс Маркета за все время, включая удалённые из отслеживания.

Удалить отдельный поисковый запрос из ежедневных проверок:

```text
/delete ID
```

`ID` берётся из `/list`. Это мягкое удаление: запрос больше не проверяется автоматически, но уже собранные точки не удаляются. На недельном графике линия заканчивается датой последней проверки, а на графике за всё время остаётся вся накопленная история.

Недельные и общие графики площадок используют только автоматические проверки. Ручные `/check` и `/checkall` не засоряют статистику.

После ежедневного автоматического отчета бот сам отправляет один PDF для каждой площадки. Если у Яндекс Маркета 26 запросов, в документе будет 27 страниц: сводка и 26 отдельных графиков. Если для площадки еще нет активных запросов, PDF не отправляется. Для ежедневной отправки в Railway должно быть `REPORT_INTERVAL_DAYS=1`.

## Недельная статистика

Каждая проверка сохраняется в `position_checks`. Текущая неделя считается с понедельника по воскресенье в `TIMEZONE`.

Когда начинается новая неделя, старые данные не удаляются. Команда `/week nm_id` просто строит график только по текущей неделе, а `/stats nm_id` берет всю историю за все недели.

На графике позиция `#1` находится сверху: чем выше линия, тем лучше карточка стоит в выдаче. Если карточка не найдена, это отмечается отдельной красной меткой в нижней части графика.

## Railway

Для Railway понадобятся переменные:

- `TELEGRAM_BOT_TOKEN`
- `SETUP_KEY`
- `DATABASE_PATH=data/wb_position_bot.db`
- `TIMEZONE=Europe/Kyiv`
- `REPORT_TIMES=09:00`
- `REPORT_INTERVAL_DAYS=1` или `2`
- `WB_DEST=-1257786`
- `WB_MAX_SEARCH_PAGES=3` — ReefAPI отдаёт до трёх страниц по 100 товаров
- `WB_REQUEST_DELAY_SECONDS=2`
- `WB_REQUEST_DELAY_JITTER_SECONDS=3`
- `WB_REQUEST_RETRIES=4`
- `WB_429_COOLDOWN_SECONDS=15`
- `REEF_API_KEY=` — секретный ключ ReefAPI для выдачи Wildberries
- `REEF_API_URL=https://api.reefapi.com/wildberries/v1/search`
- `REEF_COUNTRY=ru`
- `APIFY_API_TOKEN=` — секретный токен Apify для выдачи Яндекс Маркета
- `YM_APIFY_MAX_ITEMS=50` — сколько первых позиций Яндекса проверять за один запуск
- `YM_APIFY_TIMEOUT_SECONDS=240` — время ожидания запуска Actor
- `YM_APIFY_ENRICH_PRODUCTS=1` — получать продавцов для топ-5
- `WB_PROXY_URL=` — только для старого резервного клиента без ReefAPI
- `WB_PROXY_AUTH_TOKEN=`
- `WB_PROXY_INSECURE_SSL=0`
- `YM_REGION_ID=213` — регион Москва для выдачи Яндекс Маркета
- `YM_MAX_SEARCH_PAGES=20` — используется только резервным прямым клиентом без Apify
- `YM_REQUEST_DELAY_SECONDS=2`
- `YM_REQUEST_DELAY_JITTER_SECONDS=3`
- `YM_REQUEST_RETRIES=2`
- `YM_REQUEST_TIMEOUT=20` — предел одного запроса к Яндекс Маркету
- `YM_CHECK_TIMEOUT_SECONDS=300` — предел всей проверки одного запроса через Apify
- `YM_PROXY_URL=` — отдельный прокси Яндекса, если он действительно нужен
- `YM_PROXY_AUTH_TOKEN=`
- `YM_PROXY_INSECURE_SSL=0`
- `YM_ENRICH_SELLERS=0` — дополнительные открытия карточек продавцов выключены
- `REQUEST_TIMEOUT=60`

Яндекс Маркет не использует `WB_PROXY_URL`: прокси Wildberries и Яндекса настраиваются независимо. Если `YM_PROXY_URL` пуст, Яндекс проверяется напрямую.

Для SQLite на Railway нужен volume, смонтированный в `data/`, чтобы база не пропадала после деплоя.

## Важно по Wildberries

Основной источник поисковой выдачи WB — ReefAPI. Он возвращает живой JSON с позицией, артикулом, названием, продавцом и ценой. Поэтому база, Telegram-команды и отчёты не зависят от защиты публичного сайта WB.

Бот смотрит до трёх страниц по 100 товаров и останавливается раньше, если нашёл нужную карточку. Один успешно загруженный лист выдачи расходует один кредит ReefAPI. Неуспешные запросы повторяются автоматически.

Для включения укажи в Railway только `REEF_API_KEY`. Ключ нельзя отправлять в Telegram, добавлять в GitHub или показывать на скриншотах.

Старый прямой клиент и переменные `WB_PROXY_*` оставлены как резерв совместимости, но Decodo больше не поддерживает домены Wildberries. При наличии `REEF_API_KEY` старый путь не используется.

## Важно по Яндекс Маркету

Основной источник поисковой выдачи Яндекс Маркета — Actor `zen-studio/yandex-market-scraper-parser` на Apify. Он возвращает порядок карточек, несколько идентификаторов товара, название продавца, цену и ссылку. Бот проверяет первые `YM_APIFY_MAX_ITEMS` позиций одним запуском и не повторяет одинаковый запрос в рамках одного отчета.

Для включения добавь `APIFY_API_TOKEN` в Railway. Ключ нельзя отправлять в Telegram, добавлять в GitHub или показывать на скриншотах. Если ключ не задан, старый прямой клиент `market.yandex.ru/search` остается резервом, но он может блокироваться Яндексом.

Для надежного поиска своей карточки в `/addym` обязательно указывать ID карточки или ссылку на нее. Apify возвращает несколько ID (`oskuId`, `articleNumber`, `marketSku`, `modelId`), и бот проверяет их все. Название магазина используется как дополнительный резервный способ сопоставления.
